# Rust LSP + Autocompletion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add working Rust language-server support and autocompletion to the Neovim config via the rustaceanvim plugin.

**Architecture:** Install `rust-analyzer` on the system, then add a `rustaceanvim` plugin spec to the existing `lazy.setup` block in `init.lua`. rustaceanvim owns the Rust LSP lifecycle and is configured through the `vim.g.rustaceanvim` global. Completion capabilities are reused from the existing `blink.cmp` setup; keymaps and treesitter already cover Rust globally.

**Tech Stack:** Neovim (0.11+ native `vim.lsp` API), lazy.nvim, rustaceanvim, rust-analyzer, blink.cmp, Fedora system `cargo`/`rustc`.

## Global Constraints

- Do NOT add `rust_analyzer` to the `merge_blink_capabilities`/`vim.lsp.enable` list in the `nvim-lspconfig` config block — rustaceanvim owns the Rust client, and a second client would conflict.
- Scope is LSP + completion only. No nvim-dap / debugging.
- Follow the existing config style: server capabilities come from `require('blink.cmp').get_lsp_capabilities()`, same as clangd/pylsp/verible.

### Task 1: Install rust-analyzer and wire up rustaceanvim

**Files:**
- Modify: `init.lua` (add plugin spec inside the `require('lazy').setup({ ... })` table, around the other plugin specs, e.g. after the treesitter block near line 493)

**Interfaces:**
- Consumes: `require('blink.cmp').get_lsp_capabilities()` (already used elsewhere in `init.lua`); the global `LspAttach` autocmd (lines ~239-301) which sets all LSP keymaps for any attaching client.
- Produces: a running `rust-analyzer` client for `rust` filetype buffers, configured via the `vim.g.rustaceanvim` global.

- [ ] **Step 1: Install the language server (manual, requires sudo)**

Run:
```bash
sudo dnf install -y rust-analyzer
```

Verify:
```bash
rust-analyzer --version
```
Expected: prints a version string (e.g. `rust-analyzer 1.x.x`), not "command not found".

- [ ] **Step 2: Verify Rust LSP does NOT work yet (baseline)**

Run:
```bash
cd /tmp && cargo new rust_lsp_smoketest 2>/dev/null; nvim /tmp/rust_lsp_smoketest/src/main.rs
```
In nvim run `:lua =vim.lsp.get_clients({ bufnr = 0 })` (or `:LspInfo`).
Expected: no `rust-analyzer` client attached (empty list). Quit with `:q`.

- [ ] **Step 3: Add the rustaceanvim plugin spec to `init.lua`**

Insert this table as a new entry inside the `require('lazy').setup({ ... })` list (a natural spot is right after the `nvim-treesitter` block, before the closing `})` at line ~494):

```lua
  {
    'mrcjkb/rustaceanvim',
    version = '^6',
    lazy = false, -- plugin manages its own filetype loading
    init = function()
      vim.g.rustaceanvim = {
        server = {
          -- reuse blink.cmp completion capabilities, same as the other servers
          capabilities = require('blink.cmp').get_lsp_capabilities(),
          default_settings = {
            ['rust-analyzer'] = {
              check = { command = 'clippy' }, -- lint with clippy on save
            },
          },
        },
      }
    end,
  },
```

- [ ] **Step 4: Let lazy.nvim install the plugin**

Run:
```bash
nvim --headless "+Lazy! sync" +qa
```
Expected: exits cleanly; `mrcjkb/rustaceanvim` is cloned (check `nvim --headless "+Lazy! log" +qa` or the `~/.local/share/nvim/lazy/rustaceanvim` directory exists).

- [ ] **Step 5: Verify Rust LSP now attaches and completion works**

Run:
```bash
nvim /tmp/rust_lsp_smoketest/src/main.rs
```
In nvim:
- `:checkhealth rustaceanvim` → reports `rust-analyzer` found, no errors.
- `:lua =vim.lsp.get_clients({ bufnr = 0 })` (after a moment) → shows a client named `rust-analyzer`.
- In insert mode, type `std::` and confirm a blink completion menu appears.
- Place the cursor on a symbol and press `K` → hover doc appears; press `gd` → jumps to definition.

Expected: all of the above succeed. Quit with `:qa`.
